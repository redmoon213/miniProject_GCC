# 프로젝트 개발 로그 (miniProject)

이 파일은 프로젝트의 개발 진행 상황과 주요 변경 사항을 기록하는 누적 로그입니다.

## 📅 2026년 5월 22일 (금)

### 1. 메인 메뉴 시스템 구현
- **MainMenuUI 클래스 제작**: 게임 시작(Start) 및 종료(Quit) 기능을 가진 C++ 클래스 구현.
- **GameMode 연동**: `MyGameModeBase`에서 현재 레벨이 "MainMenu"일 경우 자동으로 UI를 띄우고 마우스 커서를 활성화하도록 수정.
- **메인 메뉴 최적화**: 메인 메뉴 레벨에서는 플레이어 Pawn의 UI 생성 및 입력 처리를 차단하여 성능 최적화 및 오작동 방지.

### 2. 보스 및 적 편의성 개선
- **보스 패턴 사운드**: 보스의 투사체 발사, 차징, 점프 공격, 이동 등 각 패턴별 전용 사운드 출력 로직 추가.
- **보스 스폰 경고**: 보스 등장 전 경고 UI가 출력되는 동안 긴박한 사운드가 함께 재생되도록 구현.
- **총알-벽 충돌**: 플레이어와 적의 총알이 "Wall" 태그가 붙은 액터(기둥 등)에 닿으면 즉시 파괴되도록 처리.

### 3. 스폰 시스템 고도화
- **내비메쉬 기반 스폰 정밀도 향상**: 몬스터가 기둥 속에 끼이는 문제를 해결하기 위해 내비메쉬 투영 범위를 축소하고 충돌 체크 로직 강화.
- **스폰 높이 동기화**: 모든 적이 플레이어의 Z값(높이)을 기준으로 스폰되게 하여 지면에 묻히거나 공중에 뜨는 현상 해결.
- **디버그 시각화**: 스폰 시도 지점을 초록색/빨간색으로 표시하는 기능을 추가했다가 검증 후 주석 처리.

### 4. 신규 스킬 구현 (E 스킬)
- **나선형 총알 (BulletPlayerSpiral)**: 플레이어 위치를 중심점으로 회전하며 바깥으로 나선형 궤적을 그리며 퍼져나가는 총알 구현.
- **입력 바인딩**: E 키를 눌러 나선형 스킬을 발동할 수 있도록 `PlayerPawn`과 연동.
- **수학적 이동 로직**: `Tick` 함수 내에서 삼각함수(`Cos`, `Sin`)와 반지름 증가 로직을 조합하여 매끄러운 나선 이동 구현.

## 🛠 트러블슈팅 및 해결 과정

### 1. 메인 메뉴 UI와 플레이어 로직 충돌
- **문제**: 메인 메뉴 레벨에서 플레이어의 게임 UI가 겹쳐 보이고, 마우스 클릭 시 총이 발사되는 현상 발생.
- **원인**: `PlayerPawn`의 `BeginPlay`가 레벨을 구분하지 않고 무조건 UI 생성 및 입력 매핑을 수행함.
- **해결**: `PlayerPawn::BeginPlay` 시작 부분에 현재 레벨 이름을 체크하는 로직을 추가하여, "MainMenu" 레벨일 경우 초기화 로직을 즉시 종료(`return`)하도록 수정.

### 2. 컴파일 에러 (EnemyBoss.cpp & EnemyFactory.cpp)
- **문제**: 코드 수정 후 `Live Coding` 실패 및 다수의 구문 에러 발생.
- **원인**: 
    - 코드 삽입 과정에서 파일 끝부분에 불필요한 중괄호(`}`)와 중복된 코드가 들어감.
    - 존재하지 않는 `FNavLocation::NavId` 및 `IsNavigationNumberValid` 함수를 사용하여 정의되지 않은 식별자 에러 발생.
- **해결**: 파일 전체를 다시 읽어 중복된 코드를 제거하고, 언리얼 엔진 표준 방식인 `ProjectPointToNavigation`의 반환값(bool)을 활용한 검증 방식으로 로직을 단순화하여 해결.

### 3. 몬스터 스폰 위치 및 끼임 문제
- **문제**: 몬스터가 스테이지 기둥 속에 스폰되어 움직이지 못하거나, 바닥 아래에 묻혀서 생성됨.
- **원인**: 
    - 내비메쉬 투영 범위(`Extent`)가 너무 넓어 기둥 내부의 가장 가까운 지점으로 잘못 보정됨.
    - 액터의 피벗(Pivot)이 중앙에 있어 바닥 좌표에 그대로 스폰 시 하반신이 매몰됨.
- **해결**: 
    - 내비메쉬 투영 범위를 `500 -> 50`으로 축소하여 정밀도를 높임.
    - `SpawnCollisionHandlingOverride`를 가장 엄격한 옵션(`DontSpawnIfColliding`)으로 변경.
    - 적이 생성될 때 플레이어의 현재 `Z`값(높이)을 참조하여 스폰 위치를 동기화함으로써 매몰 문제 해결.

## 📅 2026년 6월 1일 (월)

### 1. 탄환 오브젝트 풀링(Object Pooling) 시스템 구현
- **UBulletPoolManager 개발**: 탄환을 매번 생성/파괴하는 대신 미리 생성해둔 풀(Pool)에서 꺼내 쓰고 반환하는 관리 컴포넌트 구현.
- **메모리 최적화**: 게임 시작 시 탄환을 미리 생성(`InitializeBulletPool`)하여 런타임 중 프레임 드랍(Spike) 현상 방지.
- **탄환 클래스 연동**: `ABulletPlayerBasic`에 활성화(`ActivateBullet`) 및 비활성화(`DeactivateBullet`) 로직을 추가하여 풀링에 적합한 구조로 개선.

### 2. 플레이어 사격 로직 고도화
- **풀링 기반 사격**: 일반 사격(`Fire`) 및 Q 스킬(`SpawnFanBullets`) 모두에서 `SpawnActor` 대신 풀 매니저의 `GetBullet`을 사용하도록 변경.
- **탄퍼짐(Spread) 시스템 통합**: 최종 계산된 탄퍼짐 값을 포함한 `FTransform`을 풀 매니저에 전달하여 정확한 위치와 회전으로 탄환이 활성화되도록 구현.

## 🛠 트러블슈팅 및 해결 과정

### 1. 탄환 풀 초기화 실패 (Spawn 실패)
- **문제**: 게임 실행 시 풀에 탄환이 채워지지 않고 `SpawnActor`가 실패함.
- **원인**: `UBulletPoolManager`의 `bulletClass` 변수가 에디터에 노출되지 않아 블루프린트에서 할당되지 않았음.
- **해결**: `bulletClass`를 `UPROPERTY(EditAnywhere)`로 선언하여 에디터 상세 패널에서 `BP_BulletPlayerBasic`을 직접 할당할 수 있도록 수정.

### 2. Q 스킬(산탄) 사용 시 크래시 발생
- **문제**: Q 스킬 발사 후 탄환이 충돌할 때 게임이 강제 종료됨.
- **원인**: Q 스킬은 여전히 `SpawnActor`로 생성되고 있었으나, 탄환 내부 로직은 `poolManager->ReturnToPool`을 호출하려고 시도함. 새로 생성된 탄환은 매니저 참조가 없어(`nullptr`) Access Violation 발생.
- **해결**: Q 스킬 발사 로직도 풀링 시스템(`GetBullet`)을 사용하도록 수정하여 모든 탄환이 매니저를 정상적으로 참조하도록 통일.
